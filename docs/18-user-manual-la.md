# ຄູ່ມືຜູ້ໃຊ້ — ລະບົບເກັບເງິນພາສີທີ່ດິນ

**ແຂວງສະຫວັນນະເຂດ · Land Fee Payment MVP**
ອັບເດດ 2026-11-04 · ຂຽນຈາກໜ້າຈໍທີ່ໃຊ້ຈິງ (`public/admin/` ແລະ `mobile/`)

ຄູ່ມືນີ້ຄົບທັງ **ລະບົບຫ້ອງການ (ເວັບ back-office)** ແລະ **ແອັບມືຖືປະຊາຊົນ**.
ອ່ານຫົວຂໍ້ 1–2 ກ່ອນ ເພື່ອໃຫ້ຮູ້ລຳດັບວ່າຕ້ອງເຮັດຫຍັງກ່ອນ–ຫຼັງ, ແລ້ວຕາມ
ແຕ່ລະເມນູຈາກເທິງລົງລຸ່ມຕາມແຖບຂ້າງຊ້າຍ.

## 1. ພາບລວມ

ລະບົບເກັບ **ພາສີທີ່ດິນປີ** ຂອງແຕ່ລະຕອນດິນ. ມັນບັນທຶກທະບຽນທີ່ດິນ,
ຄິດໄລ່ຈຳນວນທີ່ຕ້ອງຊຳລະ, ບັນທຶກການຊຳລະ ແລະ ອອກລາຍງານໃຫ້ແຂວງ/ກະຊວງ.

ສູດຄິດໄລ່ມີແຖວດຽວ:

```
ພາສີປີ = ອັດຕາຕໍ່ m2 (ຕາມເຂດ + ການເຂົ້າ-ອອກທາງ) × ເນື້ອທີ່ (m2)
```

- **ເນື້ອທີ່** ມາຈາກໃບຕາດິນ, ປ້ອນຄັ້ງດຽວຕອນທະບຽນຕອນດິນ.
- **ອັດຕາຕໍ່ m2** ມາຈາກ **ເຂດປະເມີນລາຄາ** ຂອງຕອນດິນ, ບັນທຶກເພື່ອນທີ່
  **ຂໍ້ມູນພື້ນຖານ → ອັດຕາພາສີຕາມເຂດ**. ແກ້ອັດຕາແລ້ວໃຊ້ກັບທຸກຕອນດິນໃນເຂດນັ້ນ
  ໂດຍບໍ່ຕ້ອງແກ້ທີ່ລະຕອນ.

ບໍ່ມີຫຍັງເຮັດໃຫ້ຈຳນວນປ່ຽນນອກຈາກສູດນີ້ — ເຖິງເຈົ້າຂອງ, ປະເພດທຳນຶງ ຫຼື ການໃຊ້
ປະໂຫຍດຈະແນວໃດ, ສອງຕອນທີ່ເທົ່າກັນ ໃນເຂດດຽວກັນ ທາງເຂົ້າດຽວກັນ ຕ້ອງຊຳລະເທົ່າກັນ.

**ສອງທາງເຂົ້າ:**

| ທ່ານແມ່ນ… | ໃຊ້… | ສ່ວນ |
|---|---|---|
| ເຈົ້າໜ້າທີ່/ພະນັກງານແຂວງ-ເມືອງ | ເວັບຫ້ອງການ `/admin/` | ພາກ 2 |
| ປະຊາຊົນໃຊ້ມືຖື | ແອັບ **ຊຳລະຄ່າທີ່ດິນ** | ພາກ 3 |

ໜ້າຫ້ອງການເປັນພາສາລາວເປັນຫຼັກ, ປ່ຽນ EN | ລາວ ຢູ່ເທິງແຖບຂ້າງຊ້າຍ.

## 2. ລຳດັບການເຮັດວຽກ (ອ່ານກ່ອນໃຊ້)

**ຫົວໃຈຂອງລະບົບ: ຕັ້ງຂໍ້ມູນພື້ນຖານໃຫ້ຄົບກ່ອນ, ໂດຍສະເພາະ "ອັດຕາພາສີຕາມເຂດ".**
ຖ້າບ້ານ/ເຂດຍັງບໍ່ທັນມີອັດຕາ, ຕອນດິນນັ້ນຈະ **ບໍ່ອອກເປັນພາສີເລີຍ** ຫຼື ຂຶ້ນຄຳວ່າ "no rate".
ດັ່ງນັ້ນຢ່າໄປປ້ອນຕອນດິນກ່ອນທີ່ຈະຕັ້ງອັດຕາໃຫ້ຮຽບຮ້ອຍ.

ວົງຈອນການເຮັດວຽກຕາມປີ:

```
 1. ເຂົ້າສູ່ລະບົບ              →  login
 2. ຕັ້ງຂໍ້ມູນພື້ນຖານ          →  ຂໍ້ມູນພື້ນຖານ (ແຂວງ → ເມືອງ(+ຕົວອັກສອນເຂດ)
   ⚠ ວຽກນີ້ຕ້ອງກ່ອນໝູ່        →    → ບ້ານ → ອັດຕາພາສີຕາມເຂດ → ປີຄ່າພາສີ)
 3. ເປີດປີພາສີ ໃຫ້ຖືກຕ້ອງ   →  ຂໍ້ມູນພື້ນຖານ → ປີຄ່າພາສີ
 4. ທະບຽນຕອນດິນ             →  ປ້ອນຂໍ້ມູນໃບຕາດິນ / ລາຍການຂໍ້ມູນໃບຕາດິນ
 5. ຈົດເກນພັນທະ (ຖ້າບໍ່ທັນ)   →  ພາສີທີ່ດິນ → Generate (ຄືນ 02:00 ທຳອັດຕະໂນມັດ)
 6. ປະຊາຊົນຊຳລະ ແລະ ສົ່ງຫຼັກຖານ →  ແອັບມືຖື ຫຼື ຄົນໄປສູນ
 7. ເຈົ້າໜ້າທີ່ກວດສອບການຊຳລະ   →  ກວດສອບການຊຳລະ
 8. ຈັບຄູ່ສະລິບທະນາຄານ       →  ນຳເຂົ້າລາຍການທະນາຄານ
 9. ລາຍງານ                       →  ລາຍງານ
```

**ຫຼັກ:** ເຮັດຕາມເມນູຈາກເທິງລົງລຸ່ມ — ຂໍ້ມູນພື້ນຖານແມ່ນຕົ້ນທາງ, ຖືກຕ້ອງແລ້ວ
ຂັ້ນຕອນຕໍ່ໄປ (ຕອນດິນ → ພັນທະ → ການຊຳລະ → ລາຍງານ) ຈຶ່ງຖືກຕາມໝົດ.

**ການເຂົ້າສູ່ລະບົບ:** ເປີດ `https://landtax.apis.com.la/admin/` ແລ້ວໃສ່ຊື່ຜູ້ໃຊ້/ລະຫັດຜ່ານ.
ຊັດ 24 ຊົ່ວໂມງ. ທຸກຄັ້ງທີ່ເຂົ້າ/ແກ້ໄຂຖືກບັນທຶກໄວ້ໃນ Audit trail. ຫ້ອງການສາມາດ
**ຕິດຕັ້ງເປັນ PWA ເທິງມືຖື** ໄດ້ (Chrome → "Add to Home screen").

**ບົດບາດ:** `admin` (ເພີ່ມແກ້ລຶບຕອນດິນ + ບໍລິຫານຜູ້ໃຊ້/ຂໍ້ມູນພື້ນຖານ),
`officer` (ປ້ອນ/ແກ້ຕອນດິນ, ບັນທຶກ ແລະ ກວດສອບການຊຳລະ), `manager` (ເບິ່ງຢ່າງດຽວ).
super admin ເບິ່ງ/ແກ້ໄດ້ທຸກເມືອງ.

# ພາກ 2 — ຫ້ອງການ (ເວັບ back-office)

ລຳດັບແຖບຂ້າງຊ້າຍ: **ໜ້າຫຼັກ · ຂໍ້ມູນພື້ນຖານ · ປ້ອນຂໍ້ມູນໃບຕາດິນ ·
ລາຍການຂໍ້ມູນໃບຕາດິນ · ພາສີທີ່ດິນ · ກວດສອບການຊຳລະ · ນຳເຂົ້າລາຍການທະນາຄານ ·
ລາຍງານ · ຜູ້ໃຊ້**. (ຂໍ້ມູນພື້ນຖານ ແລະ ຜູ້ໃຊ້ ເຫັນສະເພາະ admin.)

## 2.1 ໜ້າຫຼັກ (Dashboard)

ໜ້າທຳອິດຫຼັງເຂົ້າລະບົບ. ບອກ "ມື້ນີ້ຢູ່ໃສ" ຕາມຂອບເຂດຂອງທ່ານ: ຈຳນວນຕອນດິນ,
ເນື້ອທີ່, ພັນທະປີນີ້, ເງິນທີ່ເກັບໄດ້ ແລະ ຈຳນວນການຊຳລະທີ່ລໍຖ້າເຈົ້າໜ້າທີ່. ແຕ່ລະ
ກາດຄລິກເຂົ້າໜ້າທີ່ແກ້ໄຂມັນ. ເບິ່ງທຸກເຊົ້າ — ຕົວເລກທີ່ບໍ່ແມ່ນສູນ ແລະ ບໍ່ແມ່ນ
ເງິນເຂົ້າ = ວຽກທີ່ຕ້ອງເຮັດ.

## 2.2 ຂໍ້ມູນພື້ນຖານ (Basic Data) — ⚠ ເຮັດກ່ອນໝູ່

ທຸກຢ່າງໃນລະບົບພຶ່ງຕໍ່ຂໍ້ມູນນີ້. ແທບເທິງ: ແຂວງ · ເມືອງ · ບ້ານ ·
ອັດຕາພາສີຕາມເຂດ · ປີຄ່າພາສີ · ຂໍ້ມູນອ້າງອີງກ່ຽວກັບຕອນດິນ.

| ແທບ | ບັນທຶກຫຍັງ | ເຕືອນ |
|---|---|---|
| **ແຂວງ** | ຂໍ້ມູນແຂວງ | ປັດຈຸບັນແຂວງດຽວ |
| **ເມືອງ** | 15 ເມືອງ + **ຕົວອັກສອນເຂດ** (zone letter) | ຕົວອັກສອນນີ້ຂຶ້ນໜ້າລະຫັດເຂດທຸກແຖວ (A–O) |
| **ບ້ານ** | ບ້ານ ແລະ ສັງກັດເມືອງ | ຫຼາຍພັນບ້ານ — ກັ່ນຕອງຕາມເມືອງກ່ອນແກ້ |
| **ອັດຕາພາສີຕາມເຂດ** ⭐ | ອັດຕາ kip/m2 ຕາມເຂດປະເມີນ × ການເຂົ້າ-ອອກທາງ | **ນີ້ຄືຕາຕະລາງພາສີ** |
| **ປີຄ່າພາສີ** | ປີເກັບພາສີ ແລະ ວັນກຳນົດຊຳລະ | ເປີດປີອະນາຄົດ = ເລີ່ມຈົດພາສີທັນທີ |
| **ຂໍ້ມູນອ້າງອີງ** | ປະເພດທາງ, ປະເພດໃບຕາ, ການໃຊ້ປະໂຫຍດ | ລະຫັດຖືກອ້າງອີງຈາກຕອນດິນ |

**⭐ ອັດຕາພາສີຕາມເຂດ — ສ່ວນສຳຄັນທີ່ສຸດ.** ຕາຕະລາງເຂດ × ການເຂົ້າ-ອອກທາງ.
ແຕ່ລະ **ບ້ານ** ຄວນຖືກຈັບຄູ່ເຂດປະເມີນໄວ້; ເມື່ອບ້ານມີເຂດແລ້ວ, ທຸກຕອນດິນໃໝ່
ໃນບ້ານນັ້ນຈະຖືກກຳນົດລາຄາຖືກຕ້ອງເອງ ໂດຍເຈົ້າໜ້າທີ່ບໍ່ຕ້ອງຕັດສິນຫຍັງ. ບ້ານທີ່
**ຍັງບໍ່ຈັບຄູ່ເຂດ** ແມ່ນສາເຫດຫຼັກທີ່ຕອນດິນຂຶ້ນ "no rate" ຫຼື ບໍ່ມີພັນທະ.

**ສອງນິໄສກັນຄຳຖາມຊ່ວຍເຫຼືອ:**
- **ຢ່າລຶບແຖວທີ່ຍັງຖືກໃຊ້** — ລະບົບຈະຫ້າມ ແລະ ບອກຈຳນວນສະເກັດທີ່ອ້າງອີງມັນ,
  ໃຫ້ໄປແກ້ຜູ້ອ້າງອີງກ່ອນ.
- **ອັດຕາເກັບປະຫວັດ** — ແກ້ອັດຕາຈະ **ເພີ່ມແຖວໃໝ່ປະຈຳວັນທີ**, ແຖວລ່າສຸດທີ່
  ບໍ່ເກີນມື້ນີ້ຈະຖືກໃຊ້. ພັນທະປີເກົ່າຍັງຄົງຈຳນວນເກົ່າ (ບໍ່ຂຽນປະຫວັດໃໝ່), ຖືກຕ້ອງ
  ຕາມຫຼັກການກວດສອບບັນຊີ (audit).

## 2.3 ປ້ອນຂໍ້ມູນໃບຕາດິນ (Parcel Entry)

ມີ 3 ແທບ: **Manual** (ມາດຕະຖານ) · **Scan** · **Import** — ບັນທຶກເຂົ້າທະບຽນດຽວກັນ.

**ແທບ Manual** ຈັດລຽງຕາມໃບຕາດິນຈິງ. ຊ່ອງທີ່ຕ້ອງໃສ່ (ສີຂຽວ): ເລກໃບຕາ · ແຂວງ/ເມືອງ/
ບ້ານ · ເຈົ້າຂອງ · **ເລກແຜນທີ່** · **ເລກຕອນດິນ** · ເນື້ອທີ່ (m2). ຂໍ້ມູນເສີມ: ປະເພດ
ໃບຕາ, ໜັງສື/ເລກ, ການໃຊ້ປະໂຫຍດ, ບັດປະຈຳຕົວ, ເບີໂທ.

ສອງປຸ່ມບັນທຶກ ແຕກຕ່າງກັນສຳຄັນ:
- **ບັນທຶກເປັນສະບັບຮ່າງ** (`draft`) — ຍັງບໍ່ຈົດພາສີ, ປະຊາຊົນບໍ່ເຫັນ, ບໍ່ນັບໃນລາຍງານ.
- **ບັນທຶກ ແລະ ຢືນຢັນ** (`confirmed`) — ຈະຖືກຈົດພາສີຕັ້ງແຕ່ຮອນຄືນຕໍ່ໄປ.

**ເຂດປະເມີນ + ການເຂົ້າ-ອອກທາງ** ຢູ່ກ່ອງສີຕ່າງຫາກ (ບໍ່ມີຢູ່ໃນໃບຕາ) — ຕົກ
ຕາມບ້ານໂດຍອັດຕະໂນມັດ, ຕັ້ງເອງແຕ່ຕອນທີ່ຕ່າງຈາກບ້ານຈິງ.

**ແທບ Scan** = ວິທີດຽວທີ່ຮູບສະແກນກາຍເປັນຕອນດິນ (ບໍ່ມີ "Scan Review" ແຍກອີກ):
1. ອັບໂຫຼດຮູບ/ສະແກນໃບຕາ (ຕ່ຳກວ່າ 500px ຖືກຫ້າມ).
2. OCR (Tesseract ລາວ+ອັງກິດ) ຕື່ມທຸກຊ່ອງ + ຄະແນນໜ້າເຊື່ອຖື.
3. **ກວດ ແລະ ແກ້ແຕ່ລະຊ່ອງ** — ຕົວໜັງສືຂຽນມື OCR ອ່ານບໍ່ອອກ ຕ້ອງພິມເອງ.
4. ເລືອກບ້ານ (ຈະກຳນົດເຂດ) ແລະ ການເຂົ້າ-ອອກທາງ.
5. **ຢືນຢັນ (Confirm)** — ສ້າງຕອນດິນ + ຈົດພັນທະປີນີ້ທັນທີ. (Discard = ລຶບຮູບທັງໝົດ.)

**ແທບ Import** ປ້ອນຫຼາຍຕອນຈາກຕາຕະລາງ: ດາວໂຫຼດ template → ຕື່ມ (1 ແຖວ/ຕອນ) →
ອັບໂຫຼດ CSV → ລະບົບບອກຜົນລະແຖວ. ກຳນົດຕອນດຽວກັນທີ່ **ເລກຕອນ + ບ້ານ**; ແຖວທີ່
ບ້ານບໍ່ມີເຂດຈະຖືກຫ້າມ (ຊື່ບ້ານ) — ໄປຈັບຄູ່ເຂດໃນ 2.2 ກ່ອນ.

## 2.4 ລາຍການຂໍ້ມູນໃບຕາດິນ (Parcels) ແລະ ໜ້າລາຍລະອຽດ

ລາຍການຄົ້ນຫາທຸກຕອນ. **ກັ່ນຕອງ:** ແຂວງ/ເມືອງ/ບ້ານ (cascade), ສະຖານະ, ເລກຕອນ,
ເລກແຜນທີ່, ເລກໃບຕາ, ຊື່ເຈົ້າຂອງ. ຖັນ: ເລກຕອນ, ເຈົ້າຂອງ, ສະຖານທີ່, ເນື້ອທີ່, ເຂດ,
ທາງ, ອັດຕາ, ພາສີ, ສະຖານະ, ວັນແກ້.

**ກິດຈະກຳໃນແຕ່ລະແຖວ / ໜ້າລາຍລະອຽດ:**

| ກິດຈະກຳ | ເຮັດຫຍັງ | ໃຜ |
|---|---|---|
| **ແກ້ໄຂ (Edit)** | ເປີດ Parcel Entry ໃໝ່ໃຫ້ຕາມທຸກຊ່ອງ | admin/officer — ຫ້າມເມື່ອມີໃບບິນ/ການຊຳລະ (ຄລິກແລ້ວຈະເຫັນເຫດຜົນ) |
| **Recompute** | ຄິດໄລ່ພັນທະປີນີ້ໃໝ່ຕາມອັດຕາປັດຈຸບັນ | admin/officer |
| **Unlink ບັນຊີປະຊາຊົນ** | ແຍກບັນຊີອອກຈາກເຈົ້າຂອງ | admin/officer (ບັນທຶກ audit) |
| **ລຶບ (Delete)** | ນຳອອກຖາວອນ | admin — ຫ້າມຖ້າເຄີຍມີເງິນເກັບ (ໄລຍະທົດລອງ: super admin ລຶບໄດ້ທຸກກໍລະນີ) |

**Recompute** ໃຊ້ຫຼັງແກ້ເນື້ອທີ່/ເຂດຂອງຕອນທີ່ຈົດແລ້ວ — ແກ້ແຕ່ປີປັດຈຸບັນ, ປີເກົ່າຄົງເກົ່າ.

## 2.5 ພາສີທີ່ດິນ (Obligations)

ໜຶ່ງແຖວຕໍ່ **ຕອນດິນຕໍ່ປີ** = ສະບັດພັນທະ (ຕອນ X ຕ້ອງຊຳລະ N ກີບ ປີ Y). ກັ່ນຕອງ: ປີພັນທະ,
ແຂວງ, ເມືອງ, ສະຖານະ, ມຸມ **All / Arrears**. ສະຫຼຸບເທິງ: ຈຳນວນ, ລວມຕ້ອງຊຳ, ຄ່າປັບ,
ຊຳລະແລ້ວ, ຄ້າງ, ເກີນກຳນົດ.

- **Generate (ຈົດເກນ):** ເລືອກປີ → Generate. ສ້າງແຕ່ຕອນທີ່ຍັງບໍ່ມີ (ກົດຊ້ຳປອດໄພ),
  ຈົດສະເພາະຕອນ `confirmed/active` ສ່ວນ `draft/scanned/archived` ບໍ່ມີພັນທະ (ຖືກຕ້ອງ
  ຕາມອອກແບບ). ຮອນອັດຕະໂນມັດ **02:00 ທຸກຄືນ** ສຳລັບປີທີ່ເປີດ, ດັ່ງນັ້ນສ່ວນຫຼາຍບໍ່ມີ
  ຫຍັງຕ້ອງ Generate ເອງ.
- **Adjust penalty:** ຊົດເຊີຍ/ຍົກເວັ້ນຄ່າປັບ 10% ແລະບັນທຶກເຫດຜົນ + ຕົວເລກກ່ອນ-ຫຼັງ (audit).

> **ຢ່າສ້າງປີຕໍ່ໜ້າ ຫຼື ປີອະນາຄົດ ແລ້ວເປີດຄ້າງໄວ້** — ຮອນຄືນບໍ່ມີຈຳກັດວັນທີ: ປີອະນາຄົດ
> ທີ່ເປີດຈະເລີ່ມຈົດພາສີທົ່ວແຂວງທັນທີ. ເປີດປີກໍຕໍ່ເມື່ອຕ້ອງການຈົດພາສີຈິງເທົ່ານັ້ນ.

## 2.6 ກວດສອບການຊຳລະ (Payment Verify)

**ແທບ ຮັບຢູ່ຫ້ອງການ (Counter, ມາດຕະຖານ)** — ວຽກປະຈຳວັນ ສຳລັບເງິນທີ່ຢູ່ໜ້າຫ້ອງການ:
ສົດ, ເຊັກ, ໂອນທະນາຄານ/ມືຖືແລ້ວເອົາສະລິບມາ. ຟອມ 2 ຊັ້ນ:
- **ຂັ້ນ 1 ກວດສອບພັນທະ:** ໃສ່ເລກຕອນ + ປີ + ວິທີ → ກົດ "ກວດສອບພັນທະ". ຜົນຈະບອກ:
  Assessed (ມີພັນທະ) / Not yet issued (ຈະສ້າງ) / Already settled (ຊຳລະແລ້ວ ຢ່າຮັບເງິນ) /
  **No zone rate (ແດງ)** = ຕອນບໍ່ມີເຂດ → ໄປແກ້ໃນ Parcel Entry/ຂໍ້ມູນພື້ນຖານ.
- **ຂັ້ນ 2 ບັນທຶກ ແລະ ປິດພັນທະ:** ເລືອກຜູ້ຊຳລະ, ຈຳນວນຮັບ (ເຕັມ/ບາງສ່ວນ), ເລກເຊັກ,
  bank ref, ຮູບຫຼັກຖານ, ໝາຍເຫດ → **ບັນທຶກ ແລະ ປິດພັນທະ**. ສົດ/ເຊັກ = PAID ທັນທີ +
  **ພິມໃບຮັບເງິນ**; ທະນາຄານ/ມືຖື = ISSUED→SUBMITTED→ກວດສອບ.

**ແທບ ແອັບມືຖື (Mobile app)** — ກຸ່ມທີ່ປະຊາຊົນອອກໃບບິນເອງຈາກແອັບ ແລະ ອັບໂຫຼດ
ສະລິບ (ຫຼື ຄູ່ຈາກສະລິບທະນາຄານ). ບັດສະເພາະແຖວ: ອັບໂຫຼດສະລິບ, **ກວດສອບ (Verify)** →
PAID+ປິດພັນທະ, **ປະຕິເສດ (Reject)** → REJECTED ພ້ອມເຫດຜົນ. ກ່ອງແດງ
"ລໍຖ້າຫຼັກຖານ" = ອ້າງວ່າຊຳລະແລ້ວແຕ່ບໍ່ມີຫຼັກຖານ — ຕິດຕໍ່ປະຊາຊົນ.

> **SUBMITTED = ໄດ້ຮັບຫຼັກຖານ, ບໍ່ແມ່ນຊຳລະແລ້ວ.** ພັນທະຍັງເປີດຈົນກວ່າເຈົ້າໜ້າທີ່ຈະກວດສອບ.

**ແທບ ທັງໝົດ (All payments)** — ບັນຊີທຸກຊ່ອງ: ພິມໃບຮັບ/ໃບບິນຄືນ, ແລະ **ຍົກເວັ້ນ
(Waive)** ພັນທະ (ຕິດສະຖານະ waive ໃຫ້ແຕ່ **ພັນທະ**, ບໍ່ແມ່ນການຊຳລະ; ບັນທຶກ audit).

## 2.7 ນຳເຂົ້າລາຍການທະນາຄານ (Bank Import)

ຈັບຄູ່ສະລິບທະນາຄານກັບການຊຳລະ: ອັບໂຫຼດ CSV (ບໍ່ຕ້ອງໃສ່ເລກຖ້ານ, ລະບົບຄາດເອງ) →
**Import & match** ຈັບຄູ່ຕາມ reference `LFE-…` (ເຕັມ/ເກີນ = ປິດອັດຕະໂນມັດ; ບາງສ່ວນ/
ຊ້ຳ/ບໍ່ຮູ້ຈັກ = ເຫຼືອໃຫ້ເຈົ້າໜ້າທີ່). ໃນ Transactions ໃຊ້ **Apply/Ignore**, ແກ້ແລ້ວໃຊ້
**Re-match**. ຫຼັງນຳເຂົ້າ ເບິ່ງລາຍງານ → Bank reconciliation.

## 2.8 ລາຍງານ (Reports)

ດາວໂຫຼດ CSV ໄດ້ທຸກລາຍງານ (ສົ່ງໃຫ້ພະນັກງານການເງິນ/ກະຊວງ). **ຂອບເຂດຖືກບັງຄັບດ້ານ server** —
ເຈົ້າໜ້າທີ່ເຫັນເມືອງຕົນເອງ, ແຂວງເຫັນທັງແຂວງ.

| ກຸ່ມ | ລາຍງານ | ຕອບ |
|---|---|---|
| ເງິນ | Collection | ເງິນເຂົ້າເທົ່າໃດ/ເມື່ອໃດ/ມາຈາກໃສ (cash-basis) |
| ເງິນ | Arrears & aging | ໃຜຄ້າງ, ຈຳນວນເທົ່າໃດ, ເກີນກຳນົດນານ |
| ເງິນ | MOF export | ຕົວເລກກົດໝາຍ: ກຳນົດ/ເກັບໄດ້/ຄ້າງ |
| ທະບຽນ | Data entry progress | ຄວາມຄືບໜ້າປ້ອນຕອນ/ສະແກນ |
| ທະບຽນ | Parcel & owner register | ທະບຽນທີ່ດິນ + ເຈົ້າຂອງ |
| ຄວາມຄຸມ | Bank reconciliation | ສະລິບທະນາຄານກົງກັບບັນຊີບໍ |
| ຄວາມຄຸມ | Rate schedule | ອັດຕາເຂດ × ທາງທີ່ບັງຄັບໃຊ້ |
| ຄວາມຄຸມ | Audit trail | ໃຜແກ້ຫຍັງ ເມື່ອໃດ (≤1000 ແຖວ, ກັ່ນຕອງຜູ້ແກ້+ວັນທີ) |

ລາຍລະອຽດແຕ່ລະລາຍງານ: `docs/16-reports.md`.

## 2.9 ຜູ້ໃຊ້ (Users) — admin ເທົ່ານັ້ນ

ສ້າງ/ແກ້ບັນຊີເຈົ້າໜ້າທີ່ (username, ລະຫັດຜ່ານ, role, ລະດັບເມືອງ/ແຂວງ, ເມືອງ), ຕັ້ງລະຫັດຜ່ານ
ໃໝ່, ເປີດ/ປິດໃຊ້. **ເຊື່ອມບັນຊີປະຊາຊົນກັບເຈົ້າຂອງ** — ສ່ວນສຳຄັນສຸດສຳລັບແອັບ:
ປະຊາຊົນຈະເຫັນຕອນດິນກໍຕໍ່ເມື່ອບັນຊີເຊື່ອມກັບເຈົ້າຂອງ (ຄົນເອງອາດເຮັດຜ່ານແອັບ 3.5
ຫຼື ເຈົ້າໜ້າທີ່ເຮັດນີ້ໄດ້, ຄົ້ນຕາມຊື່/ບັດປະຈຳຕົວ/ເບີໂທ/ເລກຕອນ). ຫ້າມປິດບັນຊີຕົນເອງ ແລະ
ບໍ່ໃຫ້ demote admin ຄົນສຸດທ້າຍ.

# ພາກ 3 — ແອັບມືຖືປະຊາຊົນ (ຊຳລະຄ່າທີ່ດິນ)

ແອັບເປັນຜູ້ເບິ່ງ ແລະ ຊຳລະ **ບໍ່ແມ່ນຜູ້ຄິດໄລ່** — ທຸກຈຳນວນມາຈາກການກຳນົດຂອງຫ້ອງການ.
ປ່ຽນອັດຕາແລ້ວແອັບຖືກຕ້ອງຄັ້ງຖັດໄປ ບໍ່ຕ້ອງອັບເດດ.

## 3.1 ເຂົ້າສູ່ລະບົບ

ໃຊ້ **ເບີໂທ** ຢ່າງດຽວ (ບໍ່ມີລະຫັດຜ່ານ, ບໍ່ມີ OTP ຕ້ອງລໍຖ້າ). ຄັ້ງທຳອິດທີ່ໃຊ້ເບີ =
ສ້າງບັນຊີ (ເຂົ້າ=ລົງທະບຽນຄືກັນ). ພິມ `020 5555 1234` / `+856 20…` / `02055551234`
ເຂົ້າໃຈວ່າເປັນເບີດຽວກັນ. ຊັດ 24 ຊົ່ວໂມງ. ມີ rate limit ປ້ອງກັນການສ້າງບັນຊີຫຼາຍເກີນໄປ.

> **ໃຜກໍຮູ້ເບີປະຊາຊົນ = ເຂົ້າສູ່ລະບົບເປັນຄົນນັ້ນໄດ້ ແລະ ເຫັນຂໍ້ມູນ.** ເລືອກນີ້ເພາະທຸກຄົນມີມືຖື.
> ສິ່ງປ້ອງກັນຄື **ການຈ່າຍບໍ່ໄດ້ຂຶ້ນກັບແອັບ**: ເງິນເຄື່ອນກໍຕໍ່ເມື່ອຈ່າຍຈິງຢູ່ທະນາຄານ
> ແລະ ເຈົ້າໜ້າທີ່ກວດສອບ — ການເຂົ້າລະບົບບໍ່ສາມາດເຄື່ອນເງິນໄດ້.

## 3.2 ຄົ້ນຫາຕອນດິນ

ຕ້ອງ **5 ຢ່າງ** ຕາມໃບຕາ: ແຂວງ · ເມືອງ · ບ້ານ · **ເລກແຜນທີ່** · **ເລກຕອນດິນ**.
ຄົບ 5 ຢ່າງກໍເລີ່ມໄດ້ (ເລກດຽວບໍ່ພໍ ເພາະເລກຕອນຊ້ຳກັນຕາມບ້ານໄດ້).
**ການຄົ້ນບໍ່ໄດ້ເພີ່ມຕອນເຂົ້າບັນຊີ** — ນັ້ນແມ່ນຂັ້ນ 3.5. ບໍ່ພົບ = ກວດເລກແຜນທີ່/
ເລກຕອນໃຫ້ກົງໃບຕາ (ສາເຫດຫຼັກ).

## 3.3 ເບິ່ງກຳນົດຈ່າຍ

ຫຼັງຄົ້ນເຫັນ: ເຈົ້າຂອງ/ເລກໃບຕາ, ເນື້ອທີ່, ເຂດ, **ຄ່າທີ່ຕ້ອງຊຳລະ**, **ຄ່າປັບ** (10%
ເມື່ອເກີນກຳນົດ), **ຄ້າງຊຳລະ**, ກຳນົດຊຳລະ, ສະຖານະ. ຖ້າບໍ່ມີຈຳນວນເລີຍ = ຕອນບໍ່ມີ
ເຂດ → ບອກຫ້ອງການ (ປະຊາຊົນແກ້ເອງບໍ່ໄດ້).

## 3.4 ຊຳລະ

```
1.ແຕະ ຊຳລະເງິນ → 2.ເຕັມ/ບາງສ່ວນ → 3.ເລືອກ ໂອນ/ມືຖື/ຢູ່ຫ້ອງ
4.ລະບົບອອກໃບບິນ (reference LFE-YYYY-xxxxxx + QR)
5.ໄປຈ່າຍຕາມ reference ນັ້ນ ທີ່ທະນາຄານ/ແອັບທະນາຄານ ຫຼື ຢູ່ເຈົ້າໜ້າທີ່
6.ຖ່າຍຮູບສະລິບ → ອັບໂຫຼດຫຼັກຖານ
7.ລໍຖ້າເມືອງກວດສອບ
```

**ຂັ້ນ 6 ຄືສິ່ງປະຊາຊົນລືມ** — ການອອກໃບບິນ **ບໍ່ແມ່ນ** ການຊຳລະ. ແນະນຳ: ຖ່າຍສະລິບທັງໃບ
ເທິງພື້ນຮາບ, ແສງສະຫວ່າງພຽງພໍ, ເລກ reference ອ່ານໄດ້ຊັດ.

## 3.5 ຕິດຕາມ ແລະ ຕອນດິນຂອງຂ້ອຍ

**ການຊຳລະຂອງຂ້ອຍ:** Issued (ລໍຖ້າຊຳລະ) → Submitted (ສົ່ງຫຼັກຖານແລ້ວ, ຍັງບໍ່ຖືກນັບວ່າ
ຈ່າຍ) → **Paid (ຊຳລະແລ້ວ = ສຳເລັດ)** / Rejected (ປະຕິເສດ, ອ່ານເຫດຜົນແລ້ວຂໍໃບໃໝ່).
**Submitted ບໍ່ແມ່ນ Paid.**

**ຕອນດິນຂອງຂ້ອຍ** ຈະມີຕອນເມື່ອ **ເພີ່ມເຂົ້າ (claim)** ໂດຍແຕະ "ເພີ່ມໃສ່ຕອນດິນຂອງຂ້ອຍ"
ຫຼັງຄົ້ນເຫັນ (ຫຼື ເຈົ້າໜ້າທີ່ເຊື່ອມໃຫ້ 2.9). ການເພີ່ມຖືກກວດດ້ວຍ **ເບີໂທຂອງເຈົ້າຂອງ**
ບັນທຶກໄວ້ — ບໍ່ກົງ = ຖືກຫ້າມ ໃຫ້ຕິດຕໍ່ຫ້ອງການ. **ເພີ່ມບໍ່ຈຳເປັນຕ້ອງຊຳລະ** —
ໃຜກໍຄົ້ນ ແລະ ຈ່າຍໃຫ້ຕອນໄດ້ (ຍາດຊີ/ຜູ້ຊື້ຊ່ວຍຈ່າຍໄດ້).

**ໝາຍເຫດໃຫ້ເຈົ້າໜ້າທີ່:** ແອັບແກ້ຂໍ້ມູນບໍ່ໄດ້ (ແກ້ເນື້ອທີ່/ເຂດ/ເຈົ້າຂອງຢູ່ຫ້ອງການ);
"ບໍ່ມີຈຳນວນ" = ບໍ່ມີເຂດ; "ຄົ້ນບໍ່ເຫັນ" = ພິມເລກຜິດ; ຄ້າງທີ່ Submitted = ຢູ່ແທບ
ແອັບມືຖືໃນກວດສອບການຊຳລະ; ຄ້າງທີ່ Issued ຫຼາຍມື້ = ກ່ອງ "ລໍຖ້າຫຼັກຖານ".

# ພາກ 4 — ອ້າງອີງ

**ສະຖານະພັນທະ:** UNPAID · PARTIAL · PAID · OVERPAID · WAIVED · DISPUTED · REFUNDED.
**ສະຖານະການຊຳລະ:** ISSUED → SUBMITTED → PAID/REJECTED (+REFUNDED). ມີ PAID ເທົ່ານັ້ນ
ປິດພັນທະ.

**ພາສີ + ຄ່າປັບ:**
```
ພາສີປີ   = ອັດຕາ (kip/m2) × ເນື້ອທີ່ (m2)
ຄ່າປັບ     = 10% ຂອງຈຳນວນຄ້າງ ເມື່ອເກີນກຳນົດ (decree 385/ປປ 2009 ມ.10)
ຄ້າງຊຳລະ = ຕ້ອງຊຳ + ຄ່າປັບ − ຊຳລະແລ້ວ
```

**ແຫຼ່ງຕົວເລກ:** ເນື້ອທີ່←ໃບຕາ · ເຂດ←ບ້ານ/ຕອນ · ທາງ←ຕອນ · ອັດຕາ←ຂໍ້ມູນພື້ນຖານ ·
ກຳນົດຊຳ←ປີຄ່າພາສີ. ປ່ຽນອັດຕາບໍ່ແກ້ຕອນ ແລະ ບໍ່ຂຽນປະຫວັດໃໝ່.

**ປັນຫາພົບເລື້ອຍ:**

| ອາການ | ສາເຫດ | ແກ້ |
|---|---|---|
